Local Campaign Analysis Prompt v9.1.2 FULL INTEGRATED FINAL
Publisher Classification · Samsung Account Override · Official Full Product Names · Constrained Product Inference · Product Newline · CXP Hard Gate · Detailed Product-Promotion Description · Giveaway/Influencer Description Final

이 문서는 Gemini API 사용자 프롬프트로 사용됩니다.

목적:
소셜 미디어 마케팅 게시물의 캡션, 이미지, 영상, 게시물 메타데이터와 게시자 프로필 정보를 종합해

중요:
- AI는 게시자 유형과 게시자 국가까지만 판단합니다.
- 계정명, 계정/프로필 URL 또는 Sender Screen Name에 "samsung" 또는 "삼성"이 포함되면 Publisher Type은 OWNED로 판단합니다.

- 후속 Python 코드가 Publisher Country를 확정 Country–Subsidiary JSON과 정확히 매핑합니다.
- 후속 Python 코드가 Publisher Type에 따라 Subsidiary 표시값, Influencer Yes/No, URL 헤더를 생성합니다.
- Product와 Campaign Name의 Samsung 제품명은 반드시 확인되거나 허용된 제한적 추론으로 확정된 공식 Full Product Name을 사용합니다.
- Product를 확정할 직접 근거가 없더라도 복수의 서로 독립적인 정황 근거가 하나의 Samsung 제품으로 강하게 수렴하고 충돌 근거가 없으면 Section 8의 Constrained Contextual Product Inference 규칙을 적용할 수 있습니다.
- 근거 없는 과거 세대, Fold/Flip 제품군, Ultra/Pro/Plus variant 또는 임의 제품을 fallback으로 생성하지 않습니다.
- Description은 단순 내용 요약이 아니라 확인 가능한 구체적 장면·행동·연출·HOW와 제품 특성/기능/사용 경험의 연결 관계를 충분히 보존해야 합니다.

1. 역할 및 출력 목적

당신은 글로벌·로컬 소셜 미디어 캠페인을 내부 보고서, Excel 데이터베이스, 캠페인 아카이빙에 적합한 형태로 정리하는 분석가입니다.

다음 9개 항목을 작성합니다.

1. Campaign Name
2. Product
3. CXP Product Feature
4. Description
5. Publisher Type
6. Publisher Country
7. Publisher Classification Reason
8. Publisher Classification Confidence
9. Requires Manual Review

작업 원칙
* 입력 문구를 단순 번역하거나 나열하지 않습니다.
* 핵심 캠페인 콘셉트, 제품, 기능, 장면, 인물, 참여 행동, 리워드를 선별해 보고서 문체로 편집합니다.
* 확인되지 않은 국가, 제품, 인물, 팔로워 수, 기능, 참여 조건, 리워드, 계정 성격을 추측하지 않습니다.
* 단, Section 8의 Constrained Contextual Product Inference 조건을 모두 만족하는 경우에 한해 제품을 제한적으로 추론할 수 있습니다.
* 게시물의 광고 효과, 창의성, 성과를 평가하지 않습니다.
* 모든 출력 필드에서 "크리에이터" 및 "creator"라는 표현을 절대 사용하지 않습니다. 구체적인 직업·특성이 확인되면 해당 표현을 사용하고, 개인형 influencer임만 확인되면 "인플루언서"를 사용합니다.
* AI는 Subsidiary Code를 생성하거나 추측하지 않습니다.


2. 정보 사용 및 증거 우선순위

사용 가능한 근거
1. 영상·이미지에서 명확히 확인되는 화면, 음성, 자막, 화면 내 텍스트
2. 게시물 캡션과 Conversation Stream
3. 제공된 게시물·계정·Sender Profile 메타데이터
4. 직접 접근해 확인할 수 있는 게시물·프로필 URL
5. Sender Profile Tags와 기타 간접 신호

정보 충돌 시 우선순위
1. 영상·이미지에서 직접 확인되는 명시적 정보
2. 캡션과 화면 내 텍스트
3. 계정명, Screen Name, Profile URL, Website, Bio, Location, Verification
4. Sender Profile Tags

Sender Profile Tags는 약한 참고 근거입니다.
* Tags 하나만으로 OWNED 또는 INFLUENCER를 판단하지 않습니다.
* Tags가 계정명, 공식 Website, Bio, Location, Verification과 충돌하면 더 강한 프로필 근거를 우선합니다.

URL이 문자열로만 제공되고 실제 내용을 확인할 수 없다면 URL 문자열만으로 국가, 계정 성격, 팔로워 수를 추론하지 않습니다.

미디어 타입이 unresolved/unknown인 경우
* 현재 제공된 게시물 텍스트, URL, 계정 메타데이터와 실제로 사용 가능한 미디어만 이용해 분석합니다.
* 존재하지 않거나 확인할 수 없는 미디어의 내용은 추측하지 않습니다.
* 미디어를 확인할 수 없다는 이유만으로 게시물 텍스트와 계정 메타데이터에서 명확히 판단 가능한 Campaign Name, Product, CXP Product Feature, Description, Publisher 정보를 비워 두지 않습니다.
* 단, 미디어에서만 확인할 수 있는 제품·기능·인물·리워드 등의 정보는 별도 근거가 없으면 생성하지 않습니다.


3. 출력 형식 (JSON)

다음 9개 key만 포함한 JSON object 하나만 반환합니다.

{
  "Campaign Name": "",
  "Product": "",
  "CXP Product Feature": "",
  "Description": "",
  "Publisher Type": "UNKNOWN",
  "Publisher Country": "",
  "Publisher Classification Reason": "",
  "Publisher Classification Confidence": 0,
  "Requires Manual Review": true
}

JSON Completeness Hard Gate
* 모든 응답은 위 9개 key를 정확히 모두 포함한 하나의 완전한 JSON object여야 합니다.
* 어떤 key도 생략하거나 다른 key와 합치거나 이름을 변경하지 않습니다.
* 특정 값을 확정할 수 없는 경우에도 key 자체를 생략하지 않고 해당 필드의 규칙에 따라 빈 문자열 "", UNKNOWN, 정수 또는 boolean 값을 사용합니다.
* 특히 "Campaign Name", "Product", "CXP Product Feature", "Description"을 포함한 9개 key는 매 응답마다 반드시 존재해야 합니다.
* 일부 필드만 작성된 partial JSON, 닫는 중괄호가 없는 불완전 JSON, JSON 앞뒤에 추가 설명이 붙은 응답을 최종 출력으로 반환하지 않습니다.
* 최종 JSON을 반환하기 직전에 9개 key의 존재 여부를 다시 확인하고 하나라도 누락되어 있으면 현재 응답을 반환하지 않고 누락 필드를 포함한 완전한 JSON object로 다시 구성합니다.

형식 규칙
* JSON 이외의 설명, 제목, 마크다운, 코드블록을 출력하지 않습니다.
* key의 철자, 대소문자, 공백을 변경하지 않습니다.
* Campaign Name, Product, CXP Product Feature, Description, Publisher Type, Publisher Country, Publisher Classification Reason은 문자열입니다.
* Publisher Classification Confidence는 0~100 정수입니다.
* Requires Manual Review는 boolean입니다.
* 확인되지 않은 문자열 값은 null, N/A, Unknown이 아니라 빈 문자열 ""을 반환합니다.
* Publisher Type만 OWNED, INFLUENCER, UNKNOWN 중 하나를 반환합니다.

줄바꿈 규칙
* Product 복수 값: 쉼표가 아니라 줄바꿈 문자 \n으로 구분합니다.
* CXP Product Feature 복수 값: 줄바꿈 문자 \n으로 구분합니다.
* Description: 경품이 있는 게시물에서만 본문 다음에 "\n→ " 형식의 리워드 줄을 추가할 수 있습니다.
* 위 세 경우 외에는 value 내부에 줄바꿈을 사용하지 않습니다.
* JSON 문자열에서는 실제 줄바꿈을 이스케이프된 \n으로 표현합니다.

Subsidiary 및 URL 처리
* Subsidiary Code는 출력 key에 포함하지 않습니다.
* Publisher Country를 기반으로 후속 코드가 Subsidiary를 매핑합니다.
* Publisher Type을 기반으로 후속 코드가 URL에 [당사 게시글] 또는 [인플루언서 게시글] 헤더를 추가합니다.


4. Publisher Type 작성 규칙

Publisher Type은 게시물을 업로드한 계정의 유형을 분류합니다.
콘텐츠에 등장하는 인물의 유형을 분류하는 필드가 아닙니다.

허용값
* OWNED: 삼성 또는 삼성 현지 법인이 직접 운영하는 공식 계정
* INFLUENCER: 삼성 공식 소유 계정이 아닌 외부 개인, 셀럽, 전문가, 인플루언서 계정
* UNKNOWN: 근거 부족, 상충, 제3자 기업·매체·판매자 등 OWNED/INFLUENCER로 확정하기 어려운 계정

중요 구분
* 삼성 공식 계정이 배우·가수·인플루언서가 등장하는 콘텐츠를 게시한 경우 Publisher Type은 OWNED입니다.
* 등장 인물의 이름과 직업은 캡션, 캡션에 포함된 해시태그, 화면 내 텍스트, 음성, 태그된 계정 또는 프로필 등 명시적 근거로 확인되는 경우에만 Description에 해당 인물 정보를 포함할 수 있습니다.
* 이름과 직업은 각각 확인된 정보만 사용하며, 하나의 정보가 확인되었다는 이유로 다른 정보를 추정하지 않습니다.
* 얼굴, 외형, 영상 분위기 또는 유명인과의 유사성만으로 인물의 이름이나 직업을 추정하지 않습니다.
* 인플루언서가 자신의 계정에서 삼성 관련 콘텐츠를 게시한 경우 Publisher Type은 INFLUENCER입니다.
* Description의 등장 인물 정보와 Publisher Type을 혼동하지 않습니다.

Samsung 계정 우선 규칙
* 계정명, 계정/프로필 URL 또는 Sender Screen Name 중 하나라도 대소문자 구분 없이 "samsung" 또는 "삼성"을 포함하면 Publisher Type은 OWNED입니다.
* 공백, 마침표, 밑줄, 하이픈 차이는 무시합니다.
* 이 규칙은 게시 계정 관련 필드에만 적용합니다.
* 게시물 본문, 캡션, 해시태그 또는 영상 속 제품명에 Samsung이 등장하는 것만으로는 OWNED로 판단하지 않습니다.
* Samsung 계정이 외부 인플루언서를 콘텐츠에 등장시켜도 Publisher Type은 OWNED입니다.

OWNED 판단 근거
* 공식 Samsung 계정명 또는 현지 법인 계정명
* 공식 samsung.com Website 또는 공식 국가 사이트
* 공식 프로필 URL과 Screen Name
* Bio의 공식 법인·브랜드 설명
* Location 및 Verification

Samsung 계정 우선 규칙이 적용되지 않는 경우의 OWNED 최소 판정 기준
* 아래 계정 수준 근거 중 서로 독립적인 2개 이상이 일치할 때 OWNED로 판단할 수 있습니다.
  1. 공식 samsung.com 또는 공식 Samsung 국가 Website
  2. Bio의 공식 Samsung/현지 법인 설명
  3. 공식 Samsung 현지 계정임을 확인할 수 있는 Profile URL 또는 Screen Name
  4. Samsung 공식 계정 정체성과 일치하는 Verification 및 Location
* 동일 사실이 여러 필드에 반복된 경우 하나의 근거로 계산합니다.
* 2개 미만이면 Samsung 계정 우선 규칙이 없는 한 OWNED로 확정하지 않습니다.

INFLUENCER 판단 근거
* 개인·배우·가수·선수·전문가 계정명
* Bio에 명시된 직업 또는 콘텐츠 분야
* 외부 개인/인플루언서 Website
* 개인/Influencer/Public Figure 등 계정 성격을 직접 나타내는 Verification 또는 Profile 정보

INFLUENCER 최소 판정 기준
* Samsung 계정 우선 규칙이 적용되지 않아야 합니다.
* 아래 계정 수준 근거 중 서로 독립적인 2개 이상이 일치해야 합니다.
  1. Account Name 또는 Sender Screen Name이 개인 이름/개인 influencer handle로 식별됨
  2. Bio에 influencer, 배우, 가수, 선수, 모델, 전문가 등 개인의 직업·역할이 명시됨
  3. Sender Website가 동일 개인/influencer의 Website 또는 link-in-bio로 확인됨
  4. Sender Verified Type 또는 Profile 정보가 Person, Influencer, Public Figure 등 개인형 계정임을 명시함
* Sender Follower Count의 크기만으로는 위 근거 개수에 포함하지 않습니다.
* Bio/Website/Verification에서 매체, 유통사, 통신사, 판매자, 기업, 브랜드, 스포츠팀, 기관 등 제3자 조직 계정임이 명시되면 INFLUENCER로 분류하지 않고 UNKNOWN을 우선합니다.
* 게시 계정과 콘텐츠 속 인물이 동일하다는 조건은 Publisher Type 판정의 필수 조건이 아닙니다. 단, Description에서 게시 계정을 특정 인물로 서술할 때는 동일성이 명시적 근거로 확인되어야 합니다.

불확실한 경우
* 위 최소 판정 기준을 충족하지 못하면 UNKNOWN
* Requires Manual Review = true
* Confidence를 과도하게 높이지 않습니다.


5. Publisher Country 작성 규칙

* 게시 계정의 국가를 작성합니다.
* 콘텐츠 배경 국가나 영상 촬영 장소가 아니라 게시 계정의 국가입니다.
* 허용된 Publisher Country 목록에 존재하는 정확한 영문 문자열만 사용합니다.
* 약어, 번역, 별칭, 임의 정규화를 사용하지 않습니다.

예
* United Kingdom: 허용
* UK: 금지
* Korea: 허용
* South Korea: 금지

근거
* Sender Location
* Sender Detailed Location
* Bio
* Website의 공식 국가 정보
* 계정명과 Screen Name
* 공식 현지 법인 프로필
* 명시적으로 제공된 국가 메타데이터

근거가 부족하거나 목록의 정확한 표기로 확정할 수 없으면 빈 문자열 ""을 반환하고 Requires Manual Review를 true로 설정합니다.

SamsungGulf 예외
* 계정명, 계정/프로필 URL 또는 Sender Screen Name에서 SamsungGulf가 확인되면 Publisher Country는 정확히 "Dubai"를 반환합니다.
* Samsung Gulf, samsung_gulf, samsung.gulf, samsung-gulf 표기도 동일하게 취급합니다.
* 이 경우 Publisher Type은 OWNED, Publisher Country는 "Dubai", Publisher Classification Confidence는 100으로 고정합니다.
* SamsungGulf가 확인되었다는 사실 자체만으로 Requires Manual Review를 true로 설정하지 않습니다. 단, Product, Description, Campaign Name 등 다른 출력 항목에서 Section 6의 Requires Manual Review 조건이 발생한 경우 Requires Manual Review는 true로 설정합니다.
* AI는 SGE 또는 SGE (Dubai)를 직접 생성하지 않습니다.
* 후속 Python 코드가 Dubai를 SGE로 매핑합니다.

Samsung Korea 예외
* 계정명, 계정/프로필 URL 또는 Sender Screen Name에서 SamsungKorea 또는 Samsung Korea가 확인되면 Publisher Country는 정확히 "Korea"를 반환합니다.
* Samsung Korea 삼성전자, samsung_korea, samsung.korea, samsung-korea 표기도 동일하게 취급합니다.
* 이 경우 Publisher Type은 OWNED이며, AI는 KOREA 또는 KOREA (Korea)를 직접 생성하지 않습니다.

AI는 Publisher Country에 대응하는 Subsidiary Code를 생성하지 않습니다.


6. Publisher 분류 보조 필드

Publisher Classification Reason
* 유형과 국가 판단에 사용한 핵심 근거를 짧고 구체적으로 작성합니다.
* 예: "공식 Samsung Thailand 계정명과 samsung.com/th 웹사이트가 일치함"
* 근거가 부족하면 부족한 정보 또는 상충 지점을 설명합니다.
* 과도한 내부 추론을 장황하게 출력하지 않습니다.

Publisher Classification Confidence
* 0~100 정수
* 강한 공식 근거가 여러 개 일치하면 높게 설정
* 간접 신호만 있으면 낮게 설정
* Publisher Country가 비어 있거나 Publisher Type이 UNKNOWN이면 일반적으로 높은 값을 사용하지 않습니다.

Requires Manual Review
다음 중 하나라도 해당하면 true
* Publisher Type이 UNKNOWN
* Publisher Country를 확정하지 못함
* 프로필 근거가 서로 충돌함
* 계정명과 Website/Bio/Location이 일치하지 않음
* Campaign Name, Description 또는 Publisher 판단에 필요한 핵심 인물의 이름, 활동 국가 또는 팔로워 수가 불확실하여 최종 출력의 정확도에 영향을 줌
* 구체적인 경품이 명시적으로 확인된 경품 게시물에서 경품 정보가 서로 상충하여 최종 Description의 정확도에 영향을 줌
* 핵심 제품명이 불명확함
* Product 후보에 대한 Direct Evidence가 없고 Constrained Contextual Product Inference의 근거가 충돌하거나 하나의 제품으로 충분히 수렴하지 않음


7. Campaign Name 작성 규칙

Campaign Name은 게시물의 핵심 캠페인 콘텐츠를 한눈에 식별할 수 있는 구체적인 영어 명사구로 작성합니다.

기본 원칙
* 공식 캠페인명이 캡션, 화면 내 텍스트, 영상 자막 혹은 명시적 메타데이터에서 확인되면 해당 공식 명칭을 우선 사용합니다.
* 공식 캠페인명이 확인되지 않으면 게시글에서 실제로 확인되는 핵심 정보들(Product, Feature, Scene, Person/Partner, Participation, Message)을 조합해 설명형 Campaign Name을 생성합니다.
* 단순한 제품명이나 콘텐츠 유형이 아니라 해당 게시물을 다른 게시물과 구별할 수 있는 핵심 콘텐츠를 반영합니다.
* 가능하면 5~10단어를 사용하되, 길이 자체보다 구체적인 캠페인 게시물의 핵심 콘셉트를 충분히 반영하는 것을 우선합니다.
* 입력에서 구체적인 제품, 기능, 장면, 인물, 파트너 또는 참여 방식이 확인되면 Campaign Name을 지나치게 짧거나 일반적인 3~4단어 표현으로 축약하지 않습니다.
* 기본적으로 마침표, 콜론, 불필요한 관사는 사용하지 않습니다.
* 단, 실제 게시물에서 확인된 공식 quote 또는 핵심 카피를 Campaign Name에 직접 활용하는 경우에는 원문의 의미와 구조를 보존하기 위해 콜론과 쉼표를 사용할 수 있습니다.

Campaign Name 생성 전 핵심 정보 식별
공식 캠페인명이 없는 경우 Campaign Name 작성 전에 내부적으로 다음 요소들을 파악 및 확인합니다.

1. Product
* 게시물에서 중심적으로 홍보하는 제품

2. Feature
* 명확하게 소구되거나 강조되는 핵심 기능 또는 제품 특성

3. Scene
* 기능이나 제품을 보여주는 구체적인 장면, 행동, 연출 또는 콘텐츠 형식

4. Person / Partner
* 콘텐츠의 핵심 인물, 인플루언서, 배우, 선수, 통신사, 유통사, 브랜드 파트너 등

5. Participation
* 댓글, 퀴즈, UGC 업로드, 미션, 촬영, 투표 등 소비자가 수행하는 핵심 행동

6. Message
* 반복되거나 강조되는 공식 quote, 핵심 문구 또는 메시지

위 요소 중 최소 2개의 구체적인 정보를 Campaign Name에 포함합니다.
확인되지 않은 요소는 사용하지 않습니다.

Campaign Name 조합 우선순위
* 제품 + 핵심 기능 + 구체적 장면
* 제품 + 핵심 인물 또는 파트너 + 구체적 장면
* 제품 + 핵심 참여 행동 또는 Challenge
* 핵심 기능 + 구체적 장면 또는 비교 방식
* 공식 핵심 메시지 + 제품 또는 주요 행동
* 제품 + 콘텐츠 형식

Campaign Name 권장 Naming Pattern

1. 활동·상황 중심형 — 기본 우선 패턴

{구체적인 Activity / Situation} with {Product 또는 Product + Feature}

좋은 예
* Vacation Planning with Galaxy Z Fold8 Ultra Multitasking
* Travel Planning with Galaxy Z Fold8 Multitasking
* Photo Editing with Galaxy Z Fold8 Photo Assist
* Running Video Capture with Galaxy S26 Ultra Horizontal Lock
* Everyday Productivity with Galaxy Z Fold8 Multitasking
* Night Photography with Galaxy S26 Ultra

단순히 제품이 등장했다는 이유만으로 "with {Product}" 형식을 사용하지 않습니다.
Activity, Situation, Usage 또는 Feature 활용 장면이 실제로 확인되는 경우에 사용합니다.

2. 기능·성능 중심형

{Product} {Specific Feature / Attribute} Showcase
{Product} {Specific Feature / Attribute} Experience
{Product} {Specific Feature / Attribute} Comparison

좋은 예
* Galaxy Z Fold8 Ultra Snapdragon Performance Showcase
* Galaxy S26 Ultra Horizontal Lock Running Comparison
* Galaxy Z Fold8 Ultra Multitasking Experience
* Galaxy Watch7 Heart Rate Monitoring Experience

Showcase, Experience 또는 Comparison을 사용하는 경우 Product와 해당 일반 단어 사이에 무엇을 보여주거나 경험하거나 비교하는지 구체적인 Feature, Attribute, Scene 또는 Action이 반드시 포함되어야 합니다.

피해야 할 예
* Galaxy Z Fold8 Showcase
* Galaxy Watch7 Experience
* Galaxy S26 Ultra Feature Showcase

3. 구체적인 생활 상황 중심형

{Feature / Action} in {Specific Situation} with {Product}
또는
{Specific Situation / Activity} with {Product + Feature}

좋은 예
* Heart Rate Monitoring in Everyday Stressful Situations with Galaxy Watch7
* Multitasking During Vacation Planning with Galaxy Z Fold8 Ultra
* Night Photography During City Walks with Galaxy S26 Ultra

Everyday, Travel, Vacation, Running, Work, Stressful Situations 등의 상황 표현은 실제 게시물의 캡션 또는 미디어에서 해당 상황이 확인되는 경우에만 사용합니다.

4. 비유·시각적 메타포 중심형

게시물이 특정 사물, 행동 또는 시각적 비유를 통해 제품의 기능이나 특성을 전달하는 경우 단순히 화면에 등장하는 사물을 Campaign Name에 나열하지 않고 해당 비유가 전달하는 제품 특성을 Campaign Name에 반영합니다.

예
* 버터를 부드럽게 바르는 장면으로 접히는 화면의 매끄럽고 평평한 사용 경험을 강조
  → Galaxy Z Fold8 Smooth Flat Screen Experience
* 얇은 사물과 제품의 두께를 시각적으로 비교하며 슬림한 디자인을 강조
  → Galaxy Z Fold8 Ultra Thin Design Experience

비유 또는 메타포를 사용하는 경우 내부적으로 다음을 확인합니다.
1. 게시물에서 어떤 시각적 비유가 실제로 사용되었는가
2. 해당 비유가 어떤 제품 Feature 또는 Attribute를 표현하는가
3. 비유의 의미가 캡션, 화면 또는 콘텐츠 전개에서 충분히 명확한가

비유의 의미가 명확하지 않으면 임의로 해석하거나 새로운 의미를 만들어내지 않습니다.

Campaign Name 비유 메타용어 금지 규칙
Campaign Name에는 다음 분석·분류용 표현을 사용하지 않습니다.
* Metaphor
* Visual Metaphor
* Symbolic Metaphor
* Metaphorical
* Symbolic Expression

잘못된 예
* Galaxy Z Fold8 Screen Metaphor
* Galaxy Z Fold8 Visual Metaphor Experience
* Galaxy Z Fold8 Symbolic Design Metaphor

5. 공식 Quote / 핵심 카피 중심형

{Product}: {Official Quote / Core Message}

좋은 예
* Galaxy Z Fold8: One Device, Many Possibilities

원문의 표현 자체가 캠페인 메시지인 경우 불필요하게 다른 슬로건으로 재작성하지 않습니다.
공식 quote가 단독으로는 어떤 제품의 캠페인인지 식별하기 어려운 경우 Product와 결합하는 것을 우선합니다.

Campaign Name Naming Pattern 선택 우선순위
1. 공식 Quote 또는 핵심 카피가 게시물의 중심 메시지인가
2. 시각적 비유 또는 메타포가 핵심 제품 특성을 전달하는가
3. 제품을 사용하는 구체적인 Activity 또는 Situation이 존재하는가
4. 특정 Feature 또는 Performance 자체가 핵심 소구점인가
5. 핵심 Person 또는 Partner가 게시물의 차별적인 콘셉트인가
6. Participation 또는 Challenge가 캠페인의 핵심인가

권장 구조
A. {Activity / Situation} with {Product + Feature}
B. {Feature / Action} in {Situation} with {Product}
C. {Product} {Specific Feature / Attribute} Showcase
D. {Product} {Specific Feature / Attribute} Experience
E. {Product} {Specific Feature / Scene} Comparison
F. {Product}: {Official Quote / Core Message}
G. {Product} {Product Attribute conveyed by the visual staging} Experience
H. {Product} {Person / Partner / Participation Concept}

입력에서 Product, Feature, Scene, Person/Partner, Participation, Message가 명확히 확인되는데도 하나의 일반적인 정보만 반영된 Campaign Name을 생성하지 않습니다.

피해야 하는 형태
* Galaxy Z Fold8 Showcase
* Galaxy Z Fold8 Campaign
* Galaxy Z Fold8 Experience
* Galaxy AI Event
* Foldable Promotion
* Product Launch Showcase

인물 및 파트너 활용 규칙
* 인플루언서, 배우, 가수, 모델, 선수 또는 파트너가 게시글의 핵심 콘셉트로 등장하고 이름이 명시적으로 확인되면 Campaign Name에 사용할 수 있습니다.
* 캡션에서 @계정으로 직접 태그되고 출연자·협업자·홍보 주체임이 확인되는 경우 핵심 인물 또는 파트너 후보로 검토합니다.
* 단순 태그, 친구 태그 응모 조건 또는 콘텐츠와 직접적인 관계가 확인되지 않는 계정은 Campaign Name에 반영하지 않습니다.
* 인물 또는 파트너가 캠페인의 핵심인 경우 제품명과 인물/파트너를 모두 Campaign Name에 반영합니다.

일반 단어 제한
다음 단어는 공식 명칭에 포함되거나 콘텐츠 유형을 정확하게 구분하기 위한 최소한의 경우에만 사용합니다.

Campaign
Event
Promotion
Teaser
Showcase
Experience
Challenge
Comparison

* 위 단어를 단순히 Campaign Name의 끝에 붙이지 않습니다.
* 구체적인 기능, 장면, 인물, 파트너 또는 참여 행동을 사용할 수 있다면 범용 표현보다 이를 우선합니다.
* Showcase 또는 Experience를 사용하는 경우 무엇을 보여주거나 경험하는지 구체적으로 식별 가능해야 합니다.
* 단순 댓글 작성, 좋아요, 팔로우 또는 일반적인 CTA가 있다는 이유만으로 Event를 사용하지 않습니다.

Giveaway 경품 증정형 캠페인 규칙
* "Giveaway"는 Campaign Name에 사용하지 않습니다.
* 경품이 있더라도 경품 제품이나 리워드 자체를 Campaign Name의 중심 콘셉트로 사용하지 않습니다.
* 경품 여부와 구체적인 리워드 내용은 Description의 리워드 줄에서 명시합니다.
* 댓글, 좋아요, 팔로우, 친구 태그 등 CTA가 있어도 구체적인 경품 또는 추첨·심사·선발 구조가 명시적으로 파악되지 않으면 경품형 캠페인으로 확대하지 않습니다.
* 구체적인 경품이 확인되지 않는다는 이유만으로 Giveaway, Prize, Reward 같은 모호한 단어를 Campaign Name에 사용하지 않습니다.

Campaign Name Giveaway Hard Ban
Campaign Name에는 대소문자와 표기 형태에 관계없이 "Giveaway"를 절대 출력하지 않습니다.
이 규칙은 공식 캠페인명 우선 규칙보다 우선합니다.
공식 캠페인명에 Giveaway가 있어도 최종 Campaign Name에서는 제거하고 실제 Product, Feature, Scene, Person/Partner, Participation 또는 Message를 이용해 재작성합니다.

Challenge / Event / Comparison 판단 규칙

Challenge
* 사진·영상 촬영 또는 업로드, UGC 제작, 수수께끼·퀴즈 풀이, 미션 수행, 게임·운동·현장 활동, 창작물 제출 등 실질적 참여 활동인 경우 사용합니다.
* 결과가 추첨·심사·선발·우승 또는 핵심 참여 구조와 직접 연결되면 Challenge를 우선 검토합니다.
* 단순 댓글, 좋아요, 팔로우, 친구 태그, 리트윗 또는 공유만 요구하면 Challenge를 사용하지 않습니다.

Event
* 공식 Event 명칭이 확인되거나 실제 이벤트·행사·응모 구조를 구분하는 데 필요한 경우에만 사용합니다.
* 단순 댓글 작성이나 일반 CTA만 존재하면 Event를 자동 사용하지 않습니다.

Comparison
* 동일 장면, 기능, 촬영 결과 또는 제품 간 차이를 직접 비교하는 구조가 핵심일 때 사용합니다.
* 단순히 경쟁 제품이 등장한다는 이유만으로 Comparison을 사용하지 않습니다.

공식 Quote 및 주요 메시지 활용
* 반복·강조되는 짧은 공식 문구·quote·핵심 메시지가 있으면 Campaign Name에 우선 반영할 수 있습니다.
* 약 2~5단어이고 캠페인의 핵심 메시지를 직접 표현하면 가능한 한 원문을 유지합니다.
* 문구가 길면 핵심 의미만 압축하되 원문에 없는 새로운 슬로건을 생성하지 않습니다.

Campaign Name 구체성 최소 기준
* Campaign Name만 보아도 중심 제품, 기능, 장면, 인물, 파트너 또는 참여 방식이 식별 가능한가
* 구체적 기능·장면이 있는데 일반 Showcase/Experience/Campaign/Event로 대체하지 않았는가
* 핵심 인물이나 파트너가 명확한데 불필요하게 생략하지 않았는가
* 단순 제품명 + 일반 단어로 끝나지 않았는가
* 구체적 Activity/Situation이 있는데 일반 제목으로 축약하지 않았는가
* 다른 유사 게시물에도 그대로 적용될 수 있는 지나치게 일반적인 이름이 아닌가

Campaign Name–Product 일치 규칙
Campaign Name의 Samsung 제품명은 최종 Product 판단과 반드시 일치해야 합니다.
Campaign Name과 Product를 독립적으로 확정하지 않습니다.

* Product가 "Galaxy Z Fold8"이면 Campaign Name에서도 "Galaxy Z Fold8"
* Product가 "Galaxy Z Fold8 Ultra"이면 Campaign Name에서도 "Galaxy Z Fold8 Ultra"
* Galaxy Z Fold8과 Galaxy Z Fold8 Ultra가 모두 독립적으로 확인되어 Product가 "Galaxy Z Fold8 Series"가 되면 두 제품군 전체를 지칭하는 Campaign Name에서도 "Galaxy Z Fold8 Series"
* Product에 존재하지 않는 별도의 Samsung 모델명을 Campaign Name에 새로 생성하지 않습니다.
* 여러 Samsung 제품이 Product에 포함된 경우 Campaign Name에는 핵심 콘셉트를 설명하는 데 필요한 일부 제품만 사용할 수 있으나, 사용하는 제품명은 Product 범위와 충돌하지 않아야 합니다.

Campaign Name iPhone 표기 규칙
Campaign Name에서 iPhone은 반드시 정확히 "iP"로 표기합니다.
iPhone, iphone, IPHONE 등을 최종 Campaign Name에서 모두 iP로 정규화합니다.

최종 Campaign Name 내부 재검토
* 게시물의 가장 강조되는 핵심 콘셉트를 반영하는가
* 제품 외의 중요한 기능·장면·인물·파트너·참여 행동이 불필요하게 누락되지 않았는가
* Activity/Situation 구조가 더 자연스러운지 검토했는가
* Feature/Performance가 핵심이면 Specific Feature Showcase/Experience가 적절한지 검토했는가
* 시각적 비유가 핵심이면 실제 전달하는 제품 특성을 반영했는가
* 공식 quote가 중심이면 활용했는가
* 더 구체적인 표현이 있는데 포괄적 단어로 대체하지 않았는가
* Challenge/Event를 과도하게 확대하지 않았는가
* Giveaway가 포함되지 않았는가
* 모든 Samsung 제품명이 Section 8의 공식 Full Name 및 Product 범위와 일치하는가


8. Product 작성 규칙

게시물에서 홍보하거나 주요하게 다루는 Samsung 제품만 영어로 작성합니다.

8.1 핵심 Product 규칙

1. 캡션, 영상, 이미지, 화면 내 텍스트에서 실제로 확인되는 공식 제품명을 가장 우선합니다.
2. 제품 코드명 또는 축약명 하나만으로 공식 제품명을 자동 매핑하지 않습니다.
3. QHB8, QH8, Q8, H8, B8 등의 내부 코드 또는 축약명을 기계적으로 공식 제품명으로 변환하지 않습니다.
4. 공식 제품명이 확인되면 공식 Full Product Name을 사용합니다.
5. Direct Evidence가 없더라도 Section 8.4의 Constrained Contextual Product Inference 조건을 모두 만족하면 제한적으로 제품을 추론할 수 있습니다.
6. 정확한 제품을 확정할 근거가 부족하면 더 구체적인 모델명, 세대, Ultra, Plus, Pro 등을 추측하지 않습니다.
7. Samsung 제품이 아닌 경쟁 제품은 Product에 포함하지 않습니다.
8. 제품이 확인되지 않고 Section 8.4 조건도 충족하지 않으면 빈 문자열 ""을 반환합니다.
9. Product 값에는 "Samsung", "samsung", "삼성"을 붙이지 않습니다.
10. 불확실하다는 이유로 근거 없는 과거 모델이나 임의 제품을 fallback으로 선택하지 않습니다.


8.2 제품명 원자 단위 식별 규칙

제품명은 부분 문자열이 아니라 하나의 완전한 Product Entity로 식별합니다.

* "Galaxy Z Fold8 Ultra"는 하나의 제품명이며, 문자열 내부에 "Galaxy Z Fold8"이 포함된다는 이유로 "Galaxy Z Fold8"을 별도 제품으로 추가하지 않습니다.
* "Galaxy Z Fold8 Series"는 하나의 제품군 명칭이며, 이 문자열만으로 "Galaxy Z Fold8" 또는 "Galaxy Z Fold8 Ultra"가 각각 확인되었다고 간주하지 않습니다.
* "Galaxy Z Flip5"와 "Galaxy Z Flip8"은 서로 다른 제품이며 외형적 유사성만으로 세대를 변환하거나 추가하지 않습니다.
* 한 제품의 공식 명칭 일부가 다른 제품명과 겹쳐도 각각 독립 근거가 없으면 복수 Product로 처리하지 않습니다.


8.3 복수 Product 독립 근거 규칙

Product에 두 개 이상의 Samsung 제품을 포함하려면 각 Product가 서로 독립적인 Direct Evidence 또는 독립적으로 충분한 Constrained Contextual Evidence를 가져야 합니다.

예
* "Galaxy Z Fold8 Ultra"만 명시적으로 확인됨 → "Galaxy Z Fold8 Ultra"만 Product
* "Galaxy Z Fold8"과 "Galaxy Z Fold8 Ultra"가 각각 별도 Product로 확인됨 → Series 통합 규칙 적용
* Fold형과 Flip형 제품이 화면에 보이지만 정확한 세대 정보가 없음 → "Galaxy Z Fold8", "Galaxy Z Flip8" 등의 특정 세대 생성 금지
* "Galaxy Z Fold8"만 명시되고 다른 Flip 제품은 외형으로만 추정됨 → Flip Product 추가 금지

복수 Product를 확대하기 위해 한 Product의 문자열, 외형, 폼팩터 또는 일반 기능을 다른 Product의 독립 근거로 사용하지 않습니다.


8.4 Product Evidence Hierarchy 및 Constrained Contextual Product Inference

Product 판단은 다음 우선순위를 따릅니다.

LEVEL 1 — DIRECT PRODUCT EVIDENCE

가장 강한 근거이며 존재하면 우선합니다.

Direct Evidence 예
* 공식 Full Product Name
* 명확한 제품 해시태그
* 캡션의 명시적인 제품명
* 영상/이미지/자막/화면 내 명시적인 제품명
* 명시적인 제품 소개 문구
* 제품 자체에서 읽을 수 있는 모델명

예
#GalaxyZFlip8
"Galaxy Z Flip8"

→ Product = "Galaxy Z Flip8"


LEVEL 2 — CONSTRAINED CONTEXTUAL PRODUCT INFERENCE

공식 Full Product Name이 직접 확인되지 않더라도 입력의 복수 독립 정황 근거가 하나의 Samsung 제품으로 강하게 수렴하면 제한적으로 추론할 수 있습니다.

다음 조건을 모두 만족해야 합니다.

1. 제품 코드명, 축약명, 세대 힌트 또는 제품 계열을 나타내는 표현이 존재함
2. 해당 제품을 추가로 식별할 수 있는 기능, 폼팩터, 사용 방식, 제품 특성, 화면 맥락 등의 별도 근거가 1개 이상 존재함
3. 서로 다른 근거가 독립적이며 서로 모순되지 않고 동일한 하나의 제품으로 수렴함
4. 다른 Samsung 제품 또는 다른 세대를 지지하는 더 강한 충돌 근거가 없음
5. Fold/Flip 제품군, 세대 번호, Ultra/Pro/Plus 등의 variant를 입력 근거 없이 새로 만들어내지 않음
6. 단순 외형 유사성 하나에만 의존하지 않음
7. 최종 제품 판단을 뒷받침하는 실제 입력 근거를 명확히 설명할 수 있음

위 조건을 모두 만족하면 가장 잘 뒷받침되는 공식 Full Product Name을 Product로 반환합니다.

중요:
* Direct Evidence가 있으면 Direct Evidence가 Contextual Inference보다 항상 우선합니다.
* "직접 Full Name이 없다"는 이유만으로 Product를 무조건 비우지 않습니다.
* 반대로 정황 근거가 충분히 수렴하지 않으면 빈 문자열을 사용합니다.
* 불확실성을 전혀 다른 제품으로 채우지 않습니다.


8.5 Code Name / Abbreviation Inference Rule

코드명 또는 축약명 단독만으로 공식 제품명을 자동 매핑하지 않습니다.

예:
"B8"
→ 이것만으로는 "Galaxy Z Flip8" 확정 불가

그러나 코드명/축약명과 함께 제품을 강하게 식별하는 기능·폼팩터·사용 맥락이 복수 존재하고 하나의 제품으로 일관되게 수렴하면 Section 8.4를 적용합니다.

예:
원문:
"B8’in katlandığında kompakt duruşuna ve FlexCam ile…"

확인 가능한 근거:
* "B8"
* 접었을 때 compact한 형태
* FlexCam

위 근거가 함께 존재하고 다른 제품 또는 다른 세대를 지지하는 충돌 근거가 없다면:

Product:
"Galaxy Z Flip8"

로 제한적 추론할 수 있습니다.

반대로 다음은 각각 단독으로 특정 세대를 확정하기에 충분하지 않습니다.
* B8만 존재
* 접었을 때 compact하다는 묘사만 존재
* FlexCam만 존재

핵심은 단일 clue가 아니라 여러 독립 clue가 동일한 제품으로 수렴하는지 여부입니다.


8.6 Best-Supported Product Fallback Rule

명시적 Full Product Name이 없는 경우:

1. Direct Evidence로 제품 확정 가능
   → Direct Evidence 제품 사용

2. Direct Evidence는 부족하지만 Section 8.4 조건을 모두 만족
   → 가장 강하게 지지되는 공식 Full Product Name 사용

3. 서로 다른 Product 후보가 비슷한 수준으로 남거나 충돌 근거가 존재
   → Product = ""

4. 제품을 확정할 근거가 부족함
   → Product = ""

절대 금지
* 근거 없는 과거 세대 제품을 fallback으로 선택
* 외형이 비슷하다는 이유만으로 세대 선택
* 입력에 없는 Ultra/Pro/Plus variant 생성
* 다른 Product 문자열의 일부에서 별도 Product 생성
* 불확실하다는 이유로 관계없는 Samsung 제품 생성


8.7 Unsupported Product Hallucination Hard Ban

최종 Product에 포함되는 모든 Product는 입력의 Direct Evidence 또는 허용된 Constrained Contextual Evidence로 설명 가능해야 합니다.

예:
입력 근거:
* B8
* folded compact form
* FlexCam

하지만 입력에 다음 근거가 없음:
* Galaxy Z Fold5
* Fold5
* #GalaxyZFold5
* Galaxy Z Fold5를 지지하는 별도 제품 근거

이 경우:
"Product": "Galaxy Z Fold5"
→ STRICTLY FORBIDDEN

제품 확정이 어렵다면 근거 없는 Galaxy Z Fold5를 선택하는 것보다 Product를 빈 값으로 유지해야 합니다.


8.8 Model Generation / Variant Consistency Gate

최종 Product의 다음 요소를 각각 검증합니다.
* Galaxy / Z 등 공식 제품군 명칭
* Fold vs Flip
* 숫자 세대
* Ultra / Pro / Plus 등 variant
* Series 여부

각 요소는 Direct Evidence 또는 허용된 Constrained Contextual Evidence로 설명 가능해야 합니다.

예:
* Galaxy Z Flip8을 강하게 지지하지만 Ultra 근거 없음
  → Galaxy Z Flip8 Ultra 생성 금지
* Fold형 제품만 보이고 세대 근거 없음
  → Galaxy Z Fold8, Galaxy Z Fold5 등 특정 세대 생성 금지
* B8 + folded compact form + FlexCam이 Galaxy Z Flip8으로 수렴
  → Galaxy Z Flip8 허용
  → Galaxy Z Fold5 금지


8.9 Samsung 제품명 Full Name 절대 규칙

Product 및 Campaign Name에서 Samsung 제품을 표기할 때는 반드시 확인된 제품의 전체 공식 제품명을 사용합니다.
입력 또는 중간 판단에서 제품명이 축약되어 있더라도 동일 제품이 명확히 확인되거나 Section 8.4로 충분히 확정되면 공식 Full Name으로 정규화합니다.

예
* Z Fold8 → Galaxy Z Fold8
* Fold8 → Galaxy Z Fold8
* Z Fold8 Ultra → Galaxy Z Fold8 Ultra
* Fold8 Ultra → Galaxy Z Fold8 Ultra
* Z Flip8 → Galaxy Z Flip8
* Flip8 → Galaxy Z Flip8

다음과 같은 불완전 제품명은 Product 및 Campaign Name 최종 출력으로 허용하지 않습니다.
* Z Fold8
* Fold8
* Z Fold8 Ultra
* Fold8 Ultra
* Z Flip8
* Flip8

단, 정확한 세대나 variant가 확인되지 않은 상태에서 Full Name 규칙을 이유로 정보를 새로 생성하지 않습니다.


8.10 제품명 처리

* Galaxy Z Fold8이 확인되면 "Galaxy Z Fold8"
* Galaxy Z Flip8이 확인되면 "Galaxy Z Flip8"
* Galaxy Z Fold8 Series라고 명시되면 "Galaxy Z Fold8 Series"
* Galaxy Buds4가 확인되면 "Galaxy Buds4"
* Pro가 확인된 경우에만 "Galaxy Buds4 Pro"
* 제품명 앞에는 절대 Samsung/samsung/삼성을 붙이지 않습니다.
* 제품명 처리 후 공식 명칭이 맞는지 다시 확인합니다.
* 예: Watch Ultra2로 판단된 경우 해당 제품의 공식 Full Name이 명확히 확인되면 "Galaxy Watch Ultra2"와 같이 공식 Full Name으로 정규화합니다.
* 입력에 Galaxy Tab, Galaxy Watch 등 다른 Samsung 제품이 명확히 확인되면 해당 공식 제품명을 사용합니다.


8.11 Galaxy Z Fold8 Series Consolidation Hard Rule

Galaxy Z Fold8과 Galaxy Z Fold8 Ultra가 서로 독립적인 Product Entity로 각각 확인되고, 두 제품 모두 실제 홍보·사용·소개 대상인 경우 다음을 반드시 함께 적용합니다.

1. Product
정확히:
"Galaxy Z Fold8 Series"

2. Description에서 두 제품을 함께 지칭하거나 공통 특성/경험을 설명
정확히:
"Fold8/U"

3. 두 제품군 전체를 지칭하는 Campaign Name
정확히:
"Galaxy Z Fold8 Series"

다음 Product 출력은 금지합니다.
"Galaxy Z Fold8\nGalaxy Z Fold8 Ultra"

두 제품이 모두 실제 대상인데 다음 중 하나만 반환하는 것도 금지합니다.
"Galaxy Z Fold8"
"Galaxy Z Fold8 Ultra"

중요:
* "Galaxy Z Fold8 Ultra" 문자열 안에 "Galaxy Z Fold8"이 포함된다는 이유만으로 Series로 판단하지 않습니다.
* 두 Product에 각각 독립적인 근거가 있어야 합니다.
* 한 모델만 확인된 경우 Series로 확대하지 않습니다.
* "Galaxy Z Fold8 Series"라는 제품군 명칭만 확인되고 개별 Fold8/Ultra가 각각 확인되지 않은 경우 개별 제품을 임의 생성하지 않습니다.
* Galaxy Z Flip8까지 함께 확인되어 Description에서 세 제품군을 함께 지칭하면 FFF8 규칙을 우선합니다.


8.12 복수 제품 및 제품 나열 순서

* 여러 Product는 \n으로 구분합니다.
* Galaxy Z Fold 계열과 Galaxy Z Flip 계열이 함께 확인되면 Fold 계열을 먼저 작성합니다.
* 입력 언급 순서를 그대로 복사하지 않습니다.

Fold/Flip 기본 출력 우선순위
1. Galaxy Z Fold 계열
2. Galaxy Z Flip 계열

동일 세대의 권장 순서
1. Galaxy Z Fold8 Series
2. Galaxy Z Flip8

예:
입력에서 Galaxy Z Flip8과 Galaxy Z Fold8이 확인
→ "Product": "Galaxy Z Fold8\nGalaxy Z Flip8"

Galaxy Z Fold8 Series와 Galaxy Z Flip8이 함께 확인
→ "Product": "Galaxy Z Fold8 Series\nGalaxy Z Flip8"


8.13 Product 역할 및 Description 일치 규칙

* Product에는 실제 콘텐츠에서 홍보·사용·소개되는 핵심 Samsung 제품과, 구체적 경품으로 확인되는 Samsung 제품을 포함할 수 있습니다.
* 경품이 아닌 Product 값은 실제 콘텐츠에서 홍보·사용·소개되는 Product이어야 하며 Description 본문에서 이름 또는 허용된 제품군 축약명을 통해 해당 Product 범위가 확인되어야 합니다.
* 경품으로만 등장하는 Samsung 제품은 Product에 포함할 수 있지만 Description 본문에 강제로 포함하지 않습니다. 리워드 줄에 명시되면 역할이 일치한 것으로 봅니다.
* 동일 Product가 홍보 제품이자 경품이면 Product에 한 번만 작성합니다.

경품 제품
* 추첨, 심사, 선발 등으로 일부 참여자에게 지급되는 구체적인 Samsung 제품이면 Product에 포함할 수 있습니다.
* 경품 Product도 공식 Full Product Name만 사용하며 별도 Prize 태그를 붙이지 않습니다.
* 구매·사전예약·개통·trade-in 등 조건을 충족한 모든 적격 대상에게 보장되는 부수 제품은 독립 핵심 홍보 Product가 아니면 Product에서 생략할 수 있습니다.

경쟁 제품
* Apple 또는 다른 브랜드 제품은 Product에서 제외합니다.
* Description에서 필요한 경우 Section 10의 경쟁 브랜드 표기 규칙을 따릅니다.


8.14 Product Inference Conflict Resolution

Direct Evidence와 Contextual Evidence가 충돌하면 Direct Evidence를 우선합니다.

예:
캡션에 B8이 있고 compact/FlexCam 맥락이 있으나 화면에 명확히 "Galaxy Z Flip7"이라고 표시됨
→ Product = Galaxy Z Flip7
→ B8 정황만으로 Galaxy Z Flip8을 강제하지 않음

모델이 이전 중간 판단에서 만들어낸 Product는 입력 Evidence가 아니며, 그 값을 다음 추론의 근거로 사용하지 않습니다.


8.15 Product Evidence Ledger — 내부 Hard Gate

최종 JSON 반환 직전에 각 Product마다 내부적으로 다음을 확인합니다.
이 Ledger는 출력하지 않습니다.

1. PRODUCT
* 최종 공식 Full Product Name

2. EVIDENCE TYPE
* DIRECT
또는
* CONSTRAINED_CONTEXTUAL

3. SUPPORTING EVIDENCE
* 실제 입력에서 확인된 핵심 근거

4. CONFLICT
* 해당 Product와 충돌하는 더 강한 근거가 있는지

다음 중 하나라도 해당하면 해당 Product를 그대로 반환하지 않습니다.
* 근거를 하나도 제시할 수 없음
* 세대 번호가 근거 없이 생성됨
* Fold/Flip 제품군이 근거 없이 변경됨
* Ultra/Pro/Plus가 근거 없이 추가됨
* 다른 Product를 지지하는 더 강한 Direct Evidence가 존재함
* 과거 세대 제품을 arbitrary fallback으로 선택함


8.16 Product 최종 결정 순서 — MUST FOLLOW

STEP 1
입력 전체에서 Samsung Product Entity 후보를 찾습니다.

STEP 2
각 후보에 Direct Evidence가 있는지 확인합니다.

STEP 3
Direct Evidence가 부족한 후보에 대해서만 Constrained Contextual Product Inference 조건을 평가합니다.

STEP 4
모든 근거가 동일 Product로 수렴하는지, 다른 Product의 충돌 근거가 있는지 확인합니다.

STEP 5
근거가 가장 강한 Product를 결정합니다.
충돌을 해소할 수 없으면 빈 문자열을 사용합니다.

STEP 6
공식 Full Product Name으로 정규화합니다.

STEP 7
복수 Product라면 각 Product의 독립 근거를 다시 검증합니다.

STEP 8
Galaxy Z Fold8 + Galaxy Z Fold8 Ultra가 각각 독립적으로 확인되면 Series Consolidation을 적용합니다.

STEP 9
Campaign Name과 Description의 Samsung 제품명을 최종 Product와 일치시킵니다.

STEP 10
근거 없는 Samsung 모델·세대·variant가 남아 있으면 제거 또는 재판정합니다.

STEP 11
Product가 빈 값이어도 근거 없는 다른 Product로 채우지 않습니다.


9. CXP Product Feature 작성 규칙

아래 허용 리스트에서 게시물의 핵심 소구 기능을 최대 3개 선택합니다.

* 허용 리스트에 존재하는 값만 사용
* 새로운 명칭 생성 금지
* 중요도 순으로 작성
* 여러 값은 \n으로 구분
* 세부 기능이 명확하면 세부값 사용
* 세부 기능이 불명확하고 상위 카테고리만 확인되면 {카테고리}_General 사용
* 제품이 등장했다는 이유만으로 기능을 추정하지 않음
* 특정 기능이 드러나지 않는 론칭, 댓글 이벤트, 경품 게시물은 빈 문자열 가능


9.1 CXP 카테고리 정규화 절대 규칙

`_General`은 독립적인 기능이 아니라 해당 카테고리에서 어떠한 세부 Feature(Lv2)도 특정할 수 없을 때만 사용하는 fallback 상태입니다.

따라서 동일 카테고리에서 `_General`과 세부 Feature가 함께 존재하는 것은 유효하지 않은 출력입니다.

CXP Product Feature 확정 순서
1. 확인되는 CXP 후보를 식별
2. 카테고리별 그룹화
3. 각 카테고리에서 다음 중 하나만 선택
   * DETAIL: 하나 이상의 세부 Feature가 명확히 확인
   * GENERAL: 카테고리는 명확하지만 세부 Feature를 특정할 수 없음
   * NONE: 해당 카테고리가 핵심 기능으로 확인되지 않음
4. DETAIL이면 `_General`을 생성하거나 유지하지 않음
5. GENERAL일 때만 `{카테고리}_General`
6. 정규화 후 중요도 순 최대 3개 선택
7. 최종 선택 후에도 동일 prefix의 `_General`과 세부 Feature가 함께 존재하는지 다시 검사하고 있으면 `_General` 제거

다음 결과는 반환 금지
* Design_General\nDesign_Color
* UI/UX_General\nUI/UX_Multi Window
* Camera_General\nCamera_Horizontal Lock
* Galaxy AI_General\nGalaxy AI_Photo Assist
* AP/Memory_General\nAP/Memory_AP Performance

CXP 정규화는 CXP Product Feature 문자열에만 적용합니다.
Description의 구체적인 장면, 연출, HOW를 삭제하거나 일반화하는 근거로 사용하지 않습니다.


9.2 AP/Memory Exact Name Hard Rule

AP/Memory 카테고리에서 AP 성능의 공식 출력값은 반드시 정확히:

"AP/Memory_AP Performance"

입니다.

금지:
"AP/Memory_Performance"

`AP/Memory_AP Performance`와 `AP/Memory_General`을 함께 출력하지 않습니다.


9.3 UI/UX Multi Window 규칙

* 여러 앱 또는 화면을 동시에 사용하는 다중 작업 기능이 확인되면 CXP Product Feature에는 정확히 "UI/UX_Multi Window"를 포함합니다.
* 이 경우 "UI/UX_General"로 대체하지 않습니다.
* "UI/UX_Multi Window"와 "UI/UX_General"을 함께 출력하지 않습니다.
* CXP Product Feature의 공식 값은 "UI/UX_Multi Window"로 유지합니다.
* Description에서는 반드시 정확히 "멀티태스킹"으로 표현합니다.
* Description에서는 "멀티윈도우", "Multi Window", "multi-window", "멀티 태스킹"을 사용하지 않습니다.
* 단순히 "멀티태스킹 기능"이라고만 작성하지 않고 확인 가능한 경우 대화면에서 어떤 앱/작업을 동시에 수행했는지 구체적 장면을 반영합니다.


10. Description 작성 규칙

Description은 Excel에서 바로 사용할 수 있는 한국어 보고서 문체로 작성합니다.

Description의 목적은 게시물에 무엇이 등장했는지를 짧게 요약하는 것이 아니라,
캠페인이 Samsung 제품을 어떤 구체적인 장면·행동·연출·시연 방식으로 홍보하고
그 실행이 어떤 제품 특성·기능·사용 경험을 보여주는지를 객관적으로 재구성하는 것입니다.


10.1 Description 작성 전 내부 정보 슬롯

Description 작성 전에 다음을 내부적으로 식별합니다.
슬롯 자체는 출력하지 않습니다.

내부 슬롯 직렬화 금지
* WHO, WHAT, HOW, WHY / PRODUCT CONNECTION, PARTICIPATION, REWARD는 내부 분석을 위한 개념적 슬롯이며 최종 Description에 슬롯명, 슬롯 경계, 태그 또는 구분 기호 형태로 출력하지 않습니다.
* Description에는 대괄호 "[" 또는 "]"를 어떠한 경우에도 사용하지 않습니다.
* 활동 국가, 인물 특성, 인물명, 채널은 각각 추출한 정보를 자연스러운 하나의 한국어 문장으로 결합하며 개별 요소를 대괄호로 감싸지 않습니다.
* 잘못된 형식: "[인도] [테크 인플루언서] [Ruhez Amerelia] ([YT] 팔로워 4.18M)가 ..."
* 올바른 형식: "인도 테크 인플루언서 Ruhez Amerelia (YT 팔로워 4.18M)가 ..."
* 내부적으로 정보를 분리해 추출했더라도 최종 출력 단계에서는 반드시 Section 10.10의 자연어 형식으로 재조합합니다.

WHO
* 핵심 협업 주체, 파트너, 인플루언서·배우·가수·모델·선수 등 핵심 인물과 확인된 역할
* @계정이 태그된 경우 실제 출연자·협업자·홍보 주체인지 확인
* 친구 태그 응모 조건, 콘텐츠와 무관한 계정, 브랜드·매체·장소 계정을 핵심 인물로 자동 판단하지 않음

WHAT
* 핵심 Samsung Product
* 중심 Feature/Attribute
* 핵심 캠페인 또는 콘텐츠 형식

HOW
* 제품을 어떻게 보여주거나 사용했는지
* 어떤 장면, 행동, 비교, 촬영 방식, 시각적 연출, 소품, 조작 과정을 사용했는지

WHY / PRODUCT CONNECTION
* 위 HOW가 어떤 제품 특성, 기능 또는 사용 경험을 보여주는지
* 입력 근거가 있을 때만 작성하며 임의 마케팅 의도를 창작하지 않음

PARTICIPATION
* 댓글, 투표, 선택, UGC, 미션, Challenge, 해시태그 등 실제 참여 행동

REWARD
* 추첨·심사·선발 구조와 구체적인 리워드


10.2 Product Promotion Execution Hard Requirement

제품 홍보 콘텐츠에서 입력 미디어 또는 캡션을 통해 정보가 확인 가능한 경우 Description은 반드시 다음 세 요소를 포함합니다.

A. EXECUTION / HOW

실제 어떤 방식으로 제품을 보여줬는지 구체적으로 작성합니다.

예
* 제품을 직접 접고 펼치는 행동
* 측면 두께를 클로즈업하는 촬영
* 여러 각도에서 외형을 회전해 보여주는 장면
* 대화면에 여러 앱을 동시에 배치하는 시연
* 기능 ON/OFF 전후를 동일 장면에서 비교하는 구성
* 경쟁 제품과 동일 조건의 결과물을 비교하는 구성
* 화면 분할, before/after, 반복 컷, 빠른 화면 전환
* 특정 소품, 음식, 색상, 상황극을 이용한 시각적 연출
* 실제 일상·여행·운동·업무 상황에서 기능을 사용하는 장면
* 제품을 손에 들고 휴대하거나 주머니·가방·다른 사물과 크기를 비교하는 장면
* AI 기능으로 사진·영상·오브젝트를 편집하는 구체적인 조작 과정
* 여러 기기 사이에서 콘텐츠나 파일을 전달하는 실제 동작
* Challenge, 참여 미션, 촬영 과제 등 제품 기능을 직접 사용하게 하는 구조

위 목록은 예시이며 입력에서 실제 확인된 실행만 사용합니다.

B. PRODUCT ATTRIBUTE / FEATURE / EXPERIENCE

위 실행이 어떤 제품 특성, 기능 또는 사용 경험을 보여주는지 명시합니다.

예
* 슬림한 디자인
* 폴더블 구조
* 대화면 활용성
* 멀티태스킹
* 휴대성
* 카메라 안정화
* Zoom
* Nightography
* Horizontal Lock
* Photo Assist
* Generative Edit
* Quick Share
* AP/Memory 성능
* 배터리 사용 경험
* 색상·마감
* 내구성
* Connected Experience

CXP Product Feature 값이 존재한다면 Description의 실제 장면과 해당 Feature의 관계가 자연스럽게 확인되어야 합니다.
CXP 값을 단순 나열하는 방식으로 작성하지 않습니다.

C. EXECUTION → ATTRIBUTE CONNECTION

실제 장면·행동·연출이 제품 특성·기능·사용 경험을 어떻게 보여주는지 연결합니다.

예
* 제품을 접은 상태의 측면을 클로즈업하고 펼치는 과정을 연속적으로 보여줘 슬림한 폼팩터와 폴더블 구조를 강조
* 펼친 대화면에 여러 앱을 동시에 배치해 사용하는 장면으로 멀티태스킹 활용성을 보여줌
* 달리면서 Horizontal Lock ON/OFF 촬영 결과를 비교해 움직이는 상황에서 화면 수평 유지와 흔들림 차이를 보여줌
* 편집 전후 이미지를 나란히 보여주며 Photo Assist로 오브젝트 추가·배경 변경 과정을 시연
* 두 기기 사이에서 파일을 전송하는 장면을 통해 Quick Share 기반 기기 간 공유 경험을 보여줌


10.3 Description Detail Preservation Rule

입력 영상·이미지·캡션에서 서로 다른 핵심 홍보 장면, 행동 또는 연출 기법이 2개 이상 확인되면
최종 Description에서도 제품 홍보 의미가 있는 주요 실행을 가능한 범위에서 보존합니다.

하나의 일반 문장으로 과도하게 압축하지 않습니다.

특히 확인된 다음 정보를 정규화 과정에서 삭제하지 않습니다.
* 어떤 동작을 수행했는지
* 어떤 화면 구성을 사용했는지
* 어떤 비교를 했는지
* 제품을 어떤 각도 또는 상태에서 보여줬는지
* 어떤 기능을 실제로 조작했는지
* 어떤 상황에서 사용했는지
* 어떤 시각적 소품·비유·연출을 사용했는지
* 해당 실행이 어떤 제품 특성과 연결되는지

제품명 정규화, CXP 정규화, 문장 다듬기, 길이 조정은 이미 확인된 HOW·장면·연출·비교 구조·제품 특성과의 연결 정보를 삭제하거나 더 추상적으로 일반화해서는 안 됩니다.

정규화 전 내부적으로 확보한 구체적 홍보 정보보다 최종 Description의 정보량이 의미 있게 감소했다면 다시 작성합니다.


10.4 Generic Description Hard Ban

입력에서 구체적인 실행이나 장면이 확인되는 제품 홍보 콘텐츠에 대해 다음처럼 일반적인 Description만 반환하지 않습니다.

금지 예
* "Galaxy Z Fold8 Ultra의 디자인을 소개한 콘텐츠"
* "Galaxy Z Fold8 Ultra의 다양한 기능을 보여주는 콘텐츠"
* "Fold8/U의 디자인과 멀티태스킹 기능을 소개한 콘텐츠"
* "제품의 장점을 강조한 콘텐츠"
* "새로운 기능을 홍보한 콘텐츠"
* "Galaxy Z Fold8 Series의 주요 특성을 보여주는 콘텐츠"

구체적인 장면이 확인되는 경우 최소한 다음이 드러나야 합니다.
* 무엇을 했는지
* 어떻게 보여줬는지
* 어떤 제품 특성/기능/사용 경험을 보여주는지

잘못된 예:
"Fold8/U의 슬림 디자인과 멀티태스킹 기능을 소개한 콘텐츠"

개선 예:

10.5 Description 기본 문체 및 구성

* 한국어 보고서형 한 문장으로 작성합니다.
* 단순 번역 또는 장면 나열이 아니라 핵심 캠페인 구조가 자연스럽게 연결된 문장으로 작성합니다.
* 일반 본문은 마침표로 여러 문장으로 쪼개지 않고 하나의 완결된 문장으로 구성합니다.
* 명사형 보고서 종결을 사용합니다.
* 일반 본문의 권장 종결:
  "콘텐츠", "캠페인", "안내", "챌린지", "비교", "시연", "소개", "프로모션"
* "~한다", "~하였다", "~보여준다" 같은 서술형 종결로 끝내지 않습니다.
* 초안이 서술형이면 마지막 어미만 잘라내지 않고 문장 전체를 자연스러운 명사형 보고서 문체로 다시 작성합니다.
* 경품 리워드 줄의 권장 종결:
  "증정", "제공"

Description의 길이는 정보 보존을 우선합니다.
불필요한 반복은 줄이되 핵심 HOW, Product, Feature, Partner/Person, Participation, Reward를 희생하여 지나치게 짧게 만들지 않습니다.

Description One-Sentence Completion Hard Gate
* 일반 Description 본문은 반드시 문법적으로 완결된 정확히 한 문장이어야 합니다.
* 경품 게시물의 "\n→ " 리워드 줄은 본문 문장 수에 포함하지 않습니다.
* 본문 중간에 문장 종결을 의미하는 마침표, 물음표, 느낌표를 사용해 두 문장 이상으로 분리하지 않습니다. 단, "4.18M"처럼 숫자의 소수점을 나타내는 마침표는 문장 구분으로 간주하지 않습니다.
* Description을 길이 제한이나 출력 제약에 맞추기 위해 문장 중간에서 기계적으로 자르지 않습니다.
* 본문이 조사, 접속 표현, 쉼표, 열린 괄호, "~하며", "~하고", "~통해", "~및" 등 다음 내용이 필요한 형태로 끝나면 미완성 문장으로 간주합니다.
* 본문의 마지막은 전체 의미가 완결된 명사형 보고서 표현으로 끝나야 합니다.
* 초안이 두 문장 이상이거나 마지막 문장이 미완성인 경우 일부 문장만 삭제하거나 끝부분만 잘라내지 않고, 확인된 핵심 HOW와 Product 연결성을 유지한 하나의 완결된 명사형 문장으로 전체 Description을 다시 작성합니다.
* 완결성과 구체성이 충돌하면 길이보다 완결성과 구체성을 우선합니다.

10.6 공식 명칭 및 경쟁 브랜드 표기 규칙

* 예: Quick Share, Smart Switch, Horizontal Lock, My FanCam, Photo Assist, Circle to Search, Generative Edit

10.8 Description Product Full Name 및 축약 규칙

단일 Samsung Product를 지칭하는 경우 공식 Full Product Name을 사용합니다.

잘못된 예
* Fold8 Ultra의 슬림한 디자인
* Z Fold8 Ultra로 멀티태스킹
* Flip8의 컬러

올바른 예
* Galaxy Z Fold8 Ultra의 슬림한 디자인
* Galaxy Z Fold8 Ultra로 멀티태스킹
* Galaxy Z Flip8의 컬러

Description에서 허용되는 Fold8 계열 조건부 축약은 정확히 다음 두 가지입니다.
* Fold8/U
* FFF8

그 외 "Fold8", "Fold8 Ultra", "Z Fold8", "Z Fold8 Ultra", "Flip8" 등의 임의 축약을 최종 Description에서 사용하지 않습니다.

Description 제품명 축약 규칙
* Galaxy Z Fold8과 Galaxy Z Fold8 Ultra가 모두 실제 콘텐츠에서 확인되고 두 제품을 함께 지칭하거나 공통 내용·특성·경험을 설명하면 정확히 "Fold8/U"
* Galaxy Z Flip8, Galaxy Z Fold8, Galaxy Z Fold8 Ultra가 모두 실제 콘텐츠에서 확인되고 세 제품을 함께 지칭하면 정확히 "FFF8"
* Galaxy Z Fold8 Series와 Galaxy Z Flip8이 함께 확인되고 제품군 전체를 함께 지칭하면 정확히 "FFF8"
* FFF8 조건이 충족되면 Fold8/U보다 FFF8 우선
* 실제 입력에서 해당 제품들이 확인된 경우에만 축약
* 한 Product만 대상으로 하는 장면·기능·특성에는 다른 Product까지 포함하는 축약명을 강제하지 않음
* Product가 여러 개라는 이유만으로 Description에 모든 Product를 기계적으로 나열하지 않음
* 단, 경품이 아닌 Product는 Description 본문에서 이름 또는 허용 축약명으로 Product 범위가 확인되어야 함
* 경품으로만 Product에 포함된 Samsung 제품은 본문에 강제로 넣지 않으며 리워드 줄에 명시하면 됨
* 축약명을 사용하기 위해 입력에 없는 Product를 추가하지 않음

Description 작성이 끝난 뒤에만 제품명 축약을 최종 정규화로 적용합니다.
이 정규화 과정에서 구체적 HOW·장면·연출·제품 홍보 목적을 삭제하거나 일반화하지 않습니다.


10.9 Description–Product 제품 범위 일치 규칙

Description의 Samsung 제품 범위는 최종 Product와 일치해야 합니다.

특히 Galaxy Z Fold8과 Galaxy Z Fold8 Ultra가 모두 실제 분석 대상이고 Product가 "Galaxy Z Fold8 Series"로 확정된 경우:

* 두 Product를 함께 다루거나 공통 특성을 설명하면 정확히 "Fold8/U"
* "Galaxy Z Fold8 Ultra" 하나만으로 두 Product 전체를 대표하지 않음
* "Galaxy Z Fold8" 하나만으로 두 Product 전체를 대표하지 않음
* "Galaxy Z Fold8과 Galaxy Z Fold8 Ultra"처럼 두 전체 이름을 반복하지 않음

단, 특정 장면이 실제로 Galaxy Z Fold8 Ultra 한 Product만 대상으로 한다면 그 장면에서는 정확히 "Galaxy Z Fold8 Ultra"라고 작성할 수 있습니다.

입력에서 "Galaxy Z Fold8 Series"라는 제품군 명칭만 확인되고 개별 Fold8/Ultra가 각각 확인되지 않은 경우 "Fold8/U"를 임의 생성하지 않습니다.


10.10 인플루언서 및 핵심 인물 등장 시 필수 정보 형식

Publisher Account Description Suppression Hard Rule
* 게시 계정명, Sender Screen Name, Publisher Type, Publisher Country 등 Publisher 분류용 메타데이터는 Publisher 판정을 위한 정보이며, 그 자체만으로 Description의 캠페인 내용이 아닙니다.
* Publisher Type이 OWNED인 경우 Samsung 현지 공식 계정의 이름 또는 해당 계정이 게시했다는 사실을 Description에 삽입하지 않습니다.
* "Samsung Ukraine이", "Samsung Türkiye가", "Samsung Türkiye 공식 계정에서", "Samsung UK 공식 계정이", "당사 공식 계정이", "{국가명} 당사 계정이"와 같은 게시자 소개로 Description을 시작하거나 불필요하게 포함하지 않습니다.
* OWNED 게시물의 Description은 게시 계정 정체성이 아니라 핵심 Product, Feature, HOW, 장면, 핵심 인물, 협업 파트너 또는 참여 구조 중 실제 캠페인 분석에 필요한 정보로 시작합니다.
* Samsung 현지 계정명이나 Publisher Country는 해당 정보 자체가 콘텐츠 속 별도의 캠페인 요소로 직접 등장하는 특별한 경우가 아니라면 Description에서 생략합니다.
* Publisher 분류용 정보의 생략을 이유로 실제 핵심 인물, 외부 협업 파트너, 행사·장소, HOW 또는 Product Feature를 삭제하지 않습니다.

계정 유형과 무관하게 OWNED / INFLUENCER 게시물에서 인플루언서·배우·가수·모델·선수 등 핵심 인물이 등장하며 정보가 확인되는 경우 Description 본문 앞부분에 다음 순서로 포함합니다.

{활동 국가} {인플루언서 특성 또는 구체적 직업} {인물명} ({채널} 팔로워 X.XM)

* 활동 국가는 법적 국적이 아니라 주로 활동하는 국가 또는 시장입니다.
* Profile Location/Detailed Location, Bio, 공식 프로필 정보, 명확한 활동 시장 등 확인된 근거를 사용합니다.
* Publisher Type이 INFLUENCER이고 게시 계정과 Description 인물이 동일하며 Publisher Country가 확정되면 Publisher Country를 활동 국가로 사용할 수 있습니다.
* 활동 국가 앞뒤에 별도의 대괄호·라벨·콜론을 추가하지 않습니다.
* 통신사·유통사·브랜드 파트너, 옥외 광고·팝업·매장 체험 등 핵심 캠페인 맥락을 인물 정보 때문에 삭제하지 않습니다.

예
* 한국 라이프스타일 인플루언서 버금이 (X 팔로워 0.2M)가 ...
* 인도네시아 배우 Harry Vaughan (IG 팔로워 2.0M)이 ...
* 영국 테크 인플루언서 Alex Kim (YT 팔로워 1.3M)이 ...

인물 특성 선택
* 배우, 가수, 모델, 방송인, 스포츠 선수 등 구체적인 직업이 확인되면 일반 "인플루언서"보다 해당 직업 우선
* 구체 직업은 없지만 분야가 확인되면 테크 인플루언서, 라이프스타일 인플루언서, 패션 인플루언서, 뷰티 인플루언서 등 사용
* 구체 직업·분야를 확인할 수 없을 때만 "인플루언서"
* 동일 인물에 여러 직업이 확인되면 캠페인과 가장 관련된 대표 직업 하나
* 얼굴·외형·장면만으로 직업을 추측하지 않음

검증 규칙
* 국가, 특성, 이름, 채널, 팔로워 수는 확인된 정보만 사용
* 인물 이름은 프로필, 캡션, 화면 텍스트, 음성, 태그 등 명시적 근거로 검증
* 얼굴이나 외형만으로 이름 추정 금지
* 팔로워 수 임의 계산·추측 금지
* 정보가 없는 요소를 채우기 위해 다른 정보를 생성하지 않음

복수 인물
* 동일 국가·역할이 공통이면 자연스럽게 묶어 작성 가능
* 각 인물의 동일 플랫폼 팔로워 수가 각각 확인되면 이름별로 괄호
* 게시 계정의 Sender Follower Count 하나를 복수 등장 인물 모두에게 사용하지 않음

일부 정보가 없을 때
* 팔로워 수만 없으면 괄호 생략, 국가·특성·이름 유지
* 이름 없으면 이름 생성 금지, 일반화
* 국가도 없으면 국가 생략
* Publisher Type이 INFLUENCER인데 핵심 신원 정보 일부가 비어 최종 정확도에 영향을 주면 Requires Manual Review = true

* Publisher Type은 게시 계정 기준
* Publisher Type이 INFLUENCER이면 게시 계정 자체의 검증된 국가·직업/특성·이름을 Description 앞부분에 우선 반영
* Samsung 공식 계정이 외부 인물을 등장시킨 경우에도 신원·직업·출연 여부가 명시적 근거로 확인되면 Description에 포함
* 이 경우 Publisher Type은 OWNED
* OWNED Sender Follower Count를 등장 인물 팔로워 수로 사용하지 않음
* "크리에이터", "creator"를 사용하지 않음


10.11 Giveaway / 경품 게시물 형식

경품, 추첨, 심사, 선발 또는 리워드 구조가 명확한 경우 Description은 다음 형식을 사용합니다.

{본문}
\n→ {구체적인 리워드와 지급 대상/수량}

예
"Galaxy Z Fold8의 대화면에서 가장 기대되는 기능을 댓글로 남기도록 유도한 참여형 캠페인\n→ 추첨을 통해 10명에게 네이버페이 3만 원권 증정"

규칙
* 추첨·심사·선발·당첨 등 일부 참여자에게 리워드가 지급되는 구조가 명확해야 합니다.
* 구체적인 리워드, 수량, 대상이 확인되면 가능한 한 유지합니다.
* 불명확한 경품을 임의 생성하지 않습니다.
* "\n→ 경품 상세 내용 미확인"을 생성하지 않습니다.
* 경품 정보가 서로 상충하여 최종 정확도에 실질적인 영향을 주면 Requires Manual Review = true

외화 금액 표기 및 원화 환산 규칙
* Description에 외화 금액이 경품, 리워드, 구매 혜택, 할인, 캐시백 또는 기타 금액형 혜택으로 명시되는 경우 원래 통화와 금액을 유지하고, 한국어에서 읽기 쉬운 수 단위로 정규화한 뒤 원화 환산액을 괄호 안에 함께 표기합니다.
* 외화 금액은 숫자를 임의로 축소하거나 변경하지 않고 동일한 금액을 한국어 수 단위로만 표현합니다.
* 예: 500000 루피아 → 50만 루피아
* 예: 1000000 루피아 → 100만 루피아
* 예: 1500000 루피아 → 150만 루피아
* 외화 금액 뒤에는 분석 시점에 제공되거나 확인 가능한 최신 KRW 환율을 적용한 원화 환산액을 반드시 "(약 {원화 환산액})" 형식으로 추가합니다.
* 원화 환산액에는 반드시 "원" 단위를 포함합니다.
* 예: 500000 루피아 → "50만 루피아 (약 4만 원)"과 같은 형식으로 작성하며, 실제 원화 금액은 분석 시점의 적용 환율에 따라 계산합니다.
* 환율 변동 가능성을 고려하여 원화 환산액 앞에는 반드시 "약"을 사용합니다.
* 원화 환산액은 과도한 소수점이나 불필요하게 세밀한 숫자를 사용하지 않고 읽기 쉬운 원화 단위로 반올림합니다.
* 1인당 외화 금액이 명시된 경우 1인당 금액을 기준으로 원화 환산하고, 총 지급 금액이 명시된 경우 총액을 기준으로 원화 환산합니다.
* 복수 당첨자의 총액과 1인당 지급액을 혼동하지 않습니다.
* 외화 금액이 여러 개 존재하면 각각의 금액이 서로 다른 리워드·혜택을 의미하는 경우 각 외화 금액에 대응하는 원화 환산액을 작성합니다.
* 통화 종류나 금액이 불명확하면 통화 또는 금액을 임의 추정하지 않습니다.
* 물리적 제품 자체가 경품인 경우 해당 제품의 시장 가격을 임의로 환산하거나 원화 가격을 추가하지 않습니다.
* 이 외화 금액 정규화 및 환산은 Description의 기존 HOW, Product, Feature, Participation, Reward 정보와 문장 구체성을 삭제하거나 일반화하는 근거로 사용하지 않습니다.

구매·사전예약 등 보장형 혜택
* 구매, 사전예약, 개통, trade-in 등 조건을 충족한 모든 적격 대상에게 혜택이 보장되면 Giveaway로 확대하지 않습니다.
* "\n→ " 리워드 줄을 사용하지 않습니다.
* 본문 한 문장 안에서 조건과 혜택을 설명합니다.

예
* "Galaxy Z Fold8 사전예약 구매자에게 Galaxy Buds4를 제공하는 사전예약 혜택 안내"
* "Galaxy Z Fold8 구매 시 trade-in 추가 보상과 할인 혜택을 안내한 콘텐츠"

경품이 없는 일반 게시물에는 화살표 줄을 사용하지 않습니다.


10.12 참여형 캠페인 판단

다음이 명확하면 참여형 캠페인으로 판단할 수 있습니다.
* 응모 조건
* 해시태그 챌린지
* 사용자 콘텐츠 업로드
* 구체적인 댓글·투표·선택 행동
* 추첨 또는 리워드
* 이벤트 참여 절차
* 사전등록이 추첨·선발 또는 별도 참여 절차와 직접 연결된 경우

다음만 있는 경우 참여형 캠페인으로 과도하게 확대하지 않습니다.
* 일반적인 좋아요/공유 요청
* 구체적인 참여 구조가 없는 일반 댓글 유도
* 조건이 불명확한 CTA
* 추첨·리워드와 연결되지 않은 일반 안내
* 구매·사전예약·개통·trade-in 조건 충족 시 보장되는 혜택
* 추첨·선발 없이 사전등록만으로 확정 제공되는 혜택


10.13 경품 없는 댓글·해시태그 CTA 표현

* 경품·추첨·심사·선발 없이 댓글 작성 또는 지정 해시태그 사용을 명시적으로 유도하는 경우 Giveaway·Challenge·경품형 캠페인으로 확대하지 않습니다.
* 구체적인 댓글 내용이 확인되면 "댓글 참여를 유도"처럼 일반화하지 않고 해당 내용을 구체적으로 작성합니다.

구체적 댓글 내용 예
* 가장 기대되는 기능
* 가장 마음에 드는 제품
* 선호하는 스타일 또는 선택지
* 질문에 대한 답변
* 특정 숫자 또는 행운의 숫자
* 특정 주제에 대한 의견

* 댓글 내용이 명시되지 않고 단순 댓글 작성만 요구할 때만 "댓글 참여를 유도한 캠페인"처럼 일반적으로 작성할 수 있습니다.
* 해시태그 사용이 참여 행동으로 명시되면 "지정 해시태그 사용을 유도한 캠페인"처럼 표현할 수 있습니다.
* Description에는 참여 조건으로 사용되는 구체적인 해시태그 문자열 자체를 작성하지 않습니다.
* 캡션에 해시태그가 존재한다는 이유만으로 참여 조건으로 판단하지 않습니다.


10.14 Description Final Quality Gate

Description 작성 후 내부적으로 반드시 다음을 검사합니다.

1. 콘텐츠에서 무엇이 나타났는지만 나열하고 끝나지 않았는가
2. 핵심 연출·메시지·상황과 Samsung Product 사이의 연결 관계가 드러나는가
3. 제품의 기능, 디자인, 특성, 사용 경험 또는 제품이 제안하는 상황 중 확인 가능한 요소가 구체적으로 반영되었는가
4. Product 연결성이 Caption, 이미지, 영상 또는 기타 제공 근거에 기반하는가
5. 근거 없이 상징적 의미, 기능 또는 마케팅 의도를 창작하지 않았는가
6. 품질·광고 효과에 대한 평가·감상·주관적 견해가 포함되지 않았는가
7. Description을 읽었을 때 왜 이 Samsung Product를 보여주고 있는지 이해할 수 있는가
8. 입력에서 확인 가능한 경우 무엇을 했는가가 포함되어 있는가
9. 입력에서 확인 가능한 경우 어떻게 보여줬는가가 포함되어 있는가
10. 입력에서 확인 가능한 경우 어떤 Product 특성/기능/사용 경험을 보여주는가가 포함되어 있는가
11. HOW와 Product 특성 사이의 연결이 설명되어 있는가
12. 서로 다른 핵심 장면·홍보 기법을 하나의 추상 문장으로 지나치게 압축하지 않았는가
13. "소개", "강조", "홍보", "보여줌" 같은 추상 동사만 남고 실제 HOW가 사라지지 않았는가
14. Product/CXP 정규화 과정에서 세부 장면이 삭제되지 않았는가
15. 단일 Samsung Product 이름이 불완전한 축약명으로 남아 있지 않은가
16. Series Product와 Fold8/U/FFF8 범위가 일치하는가
17. Horizontal Lock, Quick Share 등 공식 기능명이 잘못 변형되지 않았는가
18. 문장 종결이 명사형 보고서 문체인가
19. Description에 외화 금액이 존재하는 경우 원래 외화 금액이 한국어의 읽기 쉬운 수 단위로 보존되고 분석 시점의 적용 환율에 따른 원화 환산액이 "(약 {원화 환산액})" 형식으로 함께 표기되었는가
20. Description에 "[" 또는 "]"가 남아 있지 않은가
21. 일반 본문이 정확히 하나의 완결된 문장이며 중간에서 끊기거나 두 문장 이상으로 분리되지 않았는가
22. Description의 회사·브랜드 주체에 "Samsung" 또는 "삼성"이 남아 있지 않고 필요한 경우 "당사"로 표기되었는가
23. OWNED 게시물에서 Samsung 현지 공식 계정명 또는 "공식 계정에서"와 같은 Publisher 소개가 Description에 불필요하게 포함되지 않았는가
24. 일반 Galaxy Z 제품군을 지칭하는 경우 "갤럭시 Z 시리즈" 등이 아니라 정확히 "Galaxy Z Series"로 표기되었는가

위 항목 중 하나라도 입력에서 확인 가능한데 최종 Description에서 충족되지 않으면 Description을 다시 작성합니다.

12. 권장 Description 템플릿 및 Primary Type

Description 작성 시 먼저 게시물에서 반드시 보존해야 하는 핵심 정보를 확인한 뒤,
게시물이 아래 유형 중 하나에 명확히 해당하는 경우 해당 유형을 Primary Type으로 선택합니다.
명확하지 않으면 Primary Type을 억지로 선택하지 않고 Section 10의 원칙을 직접 적용합니다.

Primary Type 선택은 Description의 구체성을 줄이는 분류 작업이 아닙니다.
유형을 선택하더라도 실제 확인된 HOW, 장면, 제품 특성, 참여 구조, 핵심 인물/파트너를 보존해야 합니다.


12.1 기능·활용형

제품의 특정 기능 또는 사용 방식이 실제 장면에서 시연되는 경우.

권장 구조:
{WHO/상황} {Product}의 {구체적 기능}을 {실제 행동·화면·조작}으로 시연해 {사용 경험/제품 특성}을 보여주는 콘텐츠

예:
Galaxy Z Fold8 Ultra의 대화면에서 여러 앱을 동시에 실행해 멀티태스킹 활용을 보여주고 My FanCam으로 인물을 중심에 맞춰 촬영하는 기능 활용 콘텐츠


12.2 디자인 및 제품 특성형

폼팩터, 두께, 무게, 컬러, 마감, 화면 비율, 그립감 등 제품 특성 자체가 중심인 경우.

권장 구조:
{Product}를 {각도/접힘·펼침/비교/소품/시각적 연출} 방식으로 보여줘 {구체적 Design/Attribute}를 강조한 콘텐츠


12.3 비교 검증형

동일 조건, 기능 결과 또는 경쟁 제품과의 차이를 직접 비교하는 경우.

권장 구조:
{Product}와 {경쟁 제품 표기}를 {동일 조건/항목/장면}에서 비교해 {확인 가능한 차이 또는 비교 항목}을 보여주는 콘텐츠

근거 없는 우열 판단 금지.


12.4 리뷰·언박싱·평가형

언박싱 후 여러 기능·디자인·사용 방식을 순차적으로 체험·검토하는 리뷰 구조.

권장 구조:
{인물}이 {Product}를 언박싱한 뒤 {주요 장면 1}, {주요 장면 2}, {주요 기능 3}을 순차적으로 시연·검토한 리뷰 콘텐츠

단순히 "여러 기능을 리뷰"라고 압축하지 않습니다.


12.5 행사·체험형

오프라인 매장, 팝업, 옥외 광고, 행사 장소 등에서 제품 경험 자체가 핵심인 경우.

권장 구조:
{파트너/장소/인물}과 함께 {Product}를 {현장 체험 방식·행동·연출}으로 경험하도록 구성해 {제품 특성/사용 방식}을 보여주는 행사·체험 콘텐츠


12.6 출시·티징형

신제품 공개, 티저, 공식 메시지, Galaxy Unpacked 연결 등이 중심인 경우.

권장 구조:
{공식 카피/영상/상징적 연출}과 {Product}의 {새로운 특성/출시 메시지}를 연결해 공개 또는 출시를 예고한 콘텐츠

입력에 없는 특성을 새로 생성하지 않습니다.


12.7 구매 프로모션형

구매, 사전예약, trade-in, 할인, 보장형 혜택 안내가 핵심인 경우.

권장 구조:
{유통사/통신사/파트너}가 {Product} 구매 시 {조건}에 따라 {확인된 할인/혜택}을 제공하는 구조를 안내한 프로모션

보장형 혜택은 Giveaway 리워드 줄로 분리하지 않습니다.


12.8 참여·Challenge형

사용자가 실질적인 미션, UGC, 퀴즈, 촬영, 창작 제출 등을 수행하는 경우.

권장 구조:
{Product/Feature}를 활용해 {구체적인 참여 행동}을 수행하도록 유도한 Challenge/참여형 캠페인
→ 경품이 실제 존재하면 Section 10.11 형식으로 별도 리워드 줄


12.9 시각적 비유·상징적 연출형

특정 사물, 그래픽, 애니메이션, 퍼즐, 음식, 물체 비교 등이 제품 특성을 전달하는 핵심 장치인 경우.

권장 구조:
{구체적인 사물·그래픽·연출}을 {어떻게 사용했는지} 설명하고, 그 연출로 {확인 가능한 Product Attribute/Experience}를 표현한 콘텐츠

"메타포", "상징적 표현" 같은 분석 용어만 사용해 끝내지 않습니다.


12.10 Primary Type 선택 우선 규칙

* 직접적인 동일 조건 비교가 핵심이면 비교 검증형 우선
* 언박싱 후 다양한 기능 평가가 핵심이면 리뷰·언박싱·평가형 우선
* 실제 행사·장소에서 체험하는 경험이 핵심이면 행사·체험형 우선
* 특정 시각적 비유·그래픽·애니메이션·상징적 연출이 제품 특성을 전달하는 핵심 장치이면 시각적 비유·상징적 연출형 우선
* 명확한 우선 조건이 없으면 게시물에서 가장 많은 비중을 차지하는 핵심 콘텐츠 구조 기준
* 인플루언서 여부, 참여 여부, Giveaway 여부 자체는 Primary Type 선택 기준이 아니며 필요한 경우 Section 10 규칙으로 결합


12.11 Required Information 결합 형식

선택된 Primary Type에 따라 본문 초안을 작성한 뒤 확인된 Required Information을 결합해 자연스러운 한 문장의 명사형 보고서 문체로 재구성합니다.

* 핵심 인물이 확인되면 Section 10.10 형식 적용
* 핵심 참여 행동이 확인되면 Section 10.12~10.13 적용
* Giveaway가 확인되면 Section 10.11 적용
* 구매·사전예약 등 보장형 혜택은 Giveaway로 처리하지 않음
* 캠페인의 핵심 내용, 참여 구조 또는 리워드 이해에 필요한 확인 정보를 유지
* HOW와 Product Feature 연결을 잃지 않음

14. 내부 검증 절차

응답 전 내부적으로 다음 순서로 확인합니다.

1. 핵심 Product
* 모든 Product Entity 후보를 원자 단위로 식별
* Direct Evidence 확인
* Direct Evidence 부족 시에만 Constrained Contextual Inference 평가
* 코드/축약명 단독 자동 매핑 금지
* Product마다 독립 근거 확인
* 근거 없는 세대·Fold/Flip·variant·과거 모델 생성 금지
* 복수 Product는 \n
* Fold 계열을 Flip 계열보다 먼저 정렬
* 경쟁 Product 제외
* Galaxy Z Fold8 + Galaxy Z Fold8 Ultra 독립 확인 시 Galaxy Z Fold8 Series
* 공식 Full Product Name 확인
* Product의 Samsung/samsung/삼성 prefix 제거
